# 노션 문서 컨벤션 (2026-08-01 확정)

대상: 노션 `로봇연구회 ZETIN > … > 드론` 페이지 전체와 그 하위 전부.
https://app.notion.com/p/3142d27b08d3804eb85ced1ca13d8998

페이지 최상위 골격은 8절, 그 아래 문서 작성 규칙은 0~7절이다.

## 0. 정답은 레포다 (SSOT)

- 상수, 텔레메트리 필드 번호, UDP 명령 문법, 바이너리 규격의 **정답은 `docs/`와
  `firmware/`**다. 노션은 그 값을 옮겨 적는 곳이 아니다.
- 노션에는 **왜 그렇게 됐는지, 무엇을 측정했는지, 무엇을 배웠는지**를 쓴다.
- 수치를 꼭 인용해야 하면 출처 파일 경로를 같이 적는다.
- 노션과 레포가 어긋나면 **레포가 맞다.** 노션을 고친다.
- 이 규칙이 있는 이유: 2026-08-01에 같은 값이 노션·`docs/`·펌웨어 주석 세 곳에
  중복돼 있어서, 코드만 바뀌고 나머지 둘이 낡은 채로 남았다.

## 1. 분류는 토글(드롭다운)이다 — 페이지가 아니다

`💻 CODE` 토글 안에 **중첩 토글 세 개**가 있고, 페이지는 그 안에 들어간다.
분류용 허브 페이지는 만들지 않는다 — 클릭 한 번을 더 요구하면서 내용은 없는
페이지가 되기 때문이다. 분류 설명은 토글 본문 한두 줄로 끝낸다.

| 토글 | 담는 것 | 배치 순서 |
|---|---|---|
| 🧠 펌웨어 (기체) | 기체 안에서 도는 코드 | 신호 흐름 순: 하드웨어 통신 → 필터 → BMM350 → PID 제어 → 자동착륙 |
| 🖥️ 지상국 · 인터페이스 | 기체 ↔ 지상 규격, PC 도구, 테스트 인프라 | UDP 명령 → 텔레메트리/ZIMU → 지상국·개발 인프라 |
| 🛩️ 실험 · 비행 기록 | 날짜가 박힌 측정 기록, 백로그 | 최신이 위 |

새 페이지는 반드시 이 셋 중 하나 안에 만든다. CODE 토글 바로 밑에 평평하게
늘어놓지 않는다.

### MCP로 토글 안에 페이지를 넣을 때 (함정)

`create-pages`는 토글 블록을 부모로 받지 못한다. 순서가 정해져 있다.

1. `create-pages`로 **드론 페이지**를 부모로 만든다 (페이지 맨 끝에 붙는다).
2. `update-page`(`update_content`)로 목표 토글 안에 `<page url="...">제목</page>`
   줄을 넣고, 맨 끝의 같은 줄을 지운다. 한 번의 호출에서 둘 다 한다.

**대상 페이지가 이미 그 페이지의 자식이어야 이동이 된다.** 다른 페이지 밑에 있는
것을 이 방법으로 옮기려 하면 `<page>`가 조용히 `<mention-page>`(단순 링크)로
바뀌고 실제 이동은 일어나지 않는다. 그럴 때는 `move-pages`로 드론 페이지에
먼저 옮긴 뒤 2단계를 한다.

## 2. 페이지 유형 세 가지

- **설명형** — 현재 동작을 서술한다. 항상 최신 상태로 유지하고, 바뀌면 과거
  서술을 남기지 말고 고친다.
- **기록형** — 제목에 날짜를 박는다. **사후 수정 금지.** 나중에 틀린 것으로
  밝혀지면 원문을 지우지 말고 정정을 옆에 병기한다(취소선 또는 정정 콜아웃).
  잘못 든 길이 보여야 같은 실수를 반복하지 않는다.
- **백로그** — 체크박스 목록. 완료해도 지우지 말고 체크 + 결과 한 줄.

## 3. 페이지 머리 (설명형·기록형 필수)

첫 블록은 상태 콜아웃이고 다음 셋을 반드시 포함한다.

1. 상태: 구현 완료 / 벤치 검증 / 실비행 검증 / 보류 중 하나
2. 최종 검증 날짜
3. 대응하는 레포 파일 경로 (필요하면 커밋 해시)

**브랜치 상태는 적지 않는다.** main에 머지된 뒤에만 문서화한다. 예전에
"브랜치 미머지/미푸시"가 머지된 뒤로도 며칠 남아 있었다.

## 4. 표기

- 한국어로 쓴다. 코드 식별자·파일 경로·명령은 인라인 코드.
- 수식은 유니코드만: µs, °, ±, ≈, √, σ, ², ×, →. LaTeX 금지.
- 위키링크 `[[...]]` 금지. 실제 노션 링크나 레포 경로를 쓴다. 옛 페이지의
  `[[04 안전 장치]]` 같은 링크는 **가리키는 페이지가 없다** — 보이면 고친다.
- 함수·상수 표는 3열 기본형: 대상 / 하는 일 / 핵심 포인트.
- 콜아웃 아이콘: 🚦 상태, ⚠️·🚨 위험, 📌 참고, ✅ 검증됨, 🕳️ 미측정·공백.

## 5. 갱신 시점

- **main에 머지될 때** — 해당 설명형 페이지를 갱신한다.
- **규격이 바뀔 때** (UDP 명령 추가, 텔레메트리 필드 append 등) — 그날 안에.
  외부 계약이라 늦으면 지상국 파서가 깨진다.
- **세션이 끝날 때** — 그 세션에서 확정된 사실만 반영한다.

비행·벤치를 하면 기록형 페이지를 새로 만들고, 관련 설명형 페이지의 상태
콜아웃(검증 수준·날짜)을 같이 갱신한다.

## 6. 안전 관련 서술

- 실제 펌웨어 동작과 다른 안전 서술은 **버그로 취급**한다. 발견 즉시 정정한다.
  (예: "RC 끊기면 항상 즉시 시동 해제" — 현재는 호버 추정·스로틀 조건에
  따라 즉시 컷 또는 시간 기반 하강으로 나뉜다.)
- 20Hz 텔레메트리 값으로 안전 판정을 설명하지 않는다. IMU 불일치 `dG`는 20Hz에서
  실제보다 약 8배 작게 나온다. 판정 근거는 1kHz 원시 로그다.

## 7. 이 문서가 규칙의 원본이다

**규칙을 바꿀 때는 이 파일을 고친다.** 에이전트별 프로젝트 지침은 이 문서를
가리키는 포인터를 사용하고, 해당 계층에 두 지침 파일이 있으면 포인터를
동일하게 유지한다. 지침 파일의 위치·존재·Git 추적 여부는 실제 저장소에서
확인한다. 특정 머신의 `.claude/CLAUDE.md` 존재나 배포 여부를 전제로 삼지 않는다.

## 8. 드론 페이지 최상위 구조

`🚀 동아리 프로젝트` DB의 기본 템플릿을 따른다 — **`활동 한 줄 소개` 토글로
시작**하고 `## 📋 결과` 아래에 산출물을 둔다. 이 둘은 다른 프로젝트 페이지와
공유하는 골격이라 임의로 바꾸지 않는다.

```text
▸ 활동 한 줄 소개              템플릿 필수 항목
🚁 현재 상태 (콜아웃)          마지막 비행 / 검증된 것 / 아직 안 된 것 / 다음 목표
## 📋 결과
   ▸ 🔧 PCB   ▸ 💻 CODE   ▸ 📐 CAD   ▸ 기타
## ⚠️ 안전 수칙                접지 않는다
## 🗓 활동 로그 · 마일스톤      최신이 위
```

- `현재 상태`와 `안전 수칙`은 **`결과` 안에 넣지 않는다.** 산출물이 아니라
  "열어보기 전에 읽어야 하는 것"이다.
- `현재 상태`는 비행할 때마다 갱신하고 네 줄 형식을 유지한다. 이 콜아웃만
  읽어도 프로젝트가 어디까지 왔는지 알 수 있어야 한다.
- `활동 로그`는 커밋 이력에서 뽑되 **날짜와 한 줄 요약만** 쓴다. 자세한 측정은
  기록형 페이지가 갖는다.

### 내용이 비어 있을 때

- `🔧 PCB`, `📐 CAD`에 원본 링크가 없으면 공백 대신 **자료 위치 확인 필요**와
  필요한 산출물(회로·제작 파일 / 모델·리비전)을 한 줄로 적는다.
- 하드웨어 구성·BOM은 기존 페이지와 [`hardware_configuration.md`](hardware_configuration.md)를
  연결하고, 코드로 확인한 것·과거 실물 기록·미확인을 구분한다. 예비 산정을
  실제 구매 목록이나 총원가로 바꾸지 않는다.
- DB에 실제 존재하는 요약·결과 속성에는 한 줄 소개와 검증 범위를 적는다.
  확인하지 않은 팀명·팀원·담당자·진행 상태를 임의로 만들지 않는다.

### 처음 보는 사람과 작업자를 위한 배치

- 현재 상태 네 줄은 짧게 유지하고 상세 기능·실험 조건은 해당 페이지로 연결한다.
- `💻 CODE` 안에서 **처음 읽을 곳 / 작업 순서 / 현재 할 일**로 바로 이동할 수
  있게 한다. 작업 순서와 인수인계는 기존 지상국·개발 인프라 페이지에서 안내한다.
- 백로그에는 작업·다음 행동·완료 조건을 적는다. 담당자·일정이 확인되지
  않았으면 배정·진행 중으로 표시하지 않는다.
- 최신 날짜의 실험 성과가 기본 지원 코드의 성과와 같다고 가정하지 않는다.
  설명형 페이지는 기본 지원 코드에 맞추고, 실험의 코드·기체 조건은 날짜 기록에 둔다.
