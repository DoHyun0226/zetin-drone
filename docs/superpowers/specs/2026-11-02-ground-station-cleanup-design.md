# 지상국 스크립트 정리 설계 (2026-11-02)

## 1. 의도

`scripts/`에 실행 스크립트가 20개 넘게 쌓였다. 무엇을 실행해야 하는지 README 표를 봐야
알 수 있고, 같은 기능(텔레메트리 수신·표시·CSV 기록)이 여러 스크립트에 따로 들어 있다.
조종 지상국 `control_dualsense.py`는 상태를 `print`로 계속 새 줄에 찍어서, 비행 중에
값이 위로 밀려 올라가 읽을 수 없다.

사용자가 원하는 것은 두 가지다.

1. **실행 도구는 셋이면 된다** — 조종용, 영상용, 로그 분석용.
2. **조종 화면은 고정 대시보드** — 숫자는 제자리에서 바뀌고 사건만 쌓인다.

그리고 지금 스크립트들에 흩어진 **추가 기능은 하나도 잃지 않는다.**

## 2. 목표 · 비목표 · 반목표

**목표**

- 실행 진입점을 조종·영상·로그 분석 세 개로 줄인다. 나머지 기능은 그 셋의 모드·하위 명령이 된다.
- 조종 화면을 6절의 A안 대시보드로 바꾼다.
- 7절의 기능 보존 표에 있는 모든 기능이 새 도구에서 동작한다.

**비목표**

- 펌웨어 변경. UDP 명령 문법·텔레메트리 필드·CSV 열 순서는 바꾸지 않는다.
- 새 분석 기능 추가. 이번 일은 정리다.
- ToF 기반 자동착륙 구현. 그건 펌웨어 쪽 별도 작업이다(5.3의 대비만 한다).

**반목표 — 동작해도 이렇게 되면 실패다**

- 안전 흐름이 바뀐다: 시동 확인(`Armed=1` 확인 전 RC 금지), 시동 거부·재시도, 자동착륙
  표시, `resume` 확인 절차, 종료 시 `stop`, 텔레메트리 끊김 경고, RC 타임아웃·치명 고장 처리.
- 기존 회귀 시험을 지우거나 약하게 만들어 통과시킨다. 시험은 옮기고 고칠 수는 있어도
  검증하던 행동을 빼면 안 된다.
- 화면 갱신 때문에 텔레메트리 수신·RC 송신 주기가 밀린다.
- CSV·raw 로그 형식이 바뀌어 기존 분석 도구나 지난 로그를 못 읽는다.
- 터미널이 깨진 채로 끝난다(커서 숨김·raw 모드가 남는 등). 비정상 종료에서도 복구돼야 한다.

## 3. 사용자가 정한 것

- 도구 셋: 조종 / 영상 / 로그 분석 (2026-11-02).
- 조종 화면은 A안(전체 대시보드): 위 상태줄, 가운데 패널, 사건 영역, 맨 아래 명령 입력줄.
  게임패드·stdin 명령·CSV·raw 기록·안전 흐름은 그대로.
- 6절의 "제 추측" 항목도 그대로 채택: 자동착륙 중 failsafe 패널 강조, 놓치면 안 되는 경고는
  위 상태줄에도 표시, 작은 터미널에서는 줄인 배치, 종료 후 사건 목록을 터미널에 남김.
- 스크립트 묶음은 5.1 표대로. 옛 벤치·전용 펌웨어 도구는 `scripts/archive/`로.
- 자동착륙은 앞으로 ToF로 바닥 거리를 재는 방식으로 바뀐다. 화면은 이것을 염두에 둔다.
- 작업은 `feat/flow-position-hold`가 main에 머지된 뒤 시작한다(같은 파일을 건드린다).
- **조종은 패드로만 한다.** `--keyboard` 모드는 설정·읽기용이다. RC를 보내지 않으므로 시동이
  걸리면 펌웨어 RC 타임아웃 failsafe가 작동한다. 그래서 이 모드는 `start`·`resume`을 보내지 않고
  거부 사유를 사건으로 띄운다. 종료 시에는 아무것도 보내지 않는다(`tune_pid.py`와 같다).
  - 정정(2026-11-03, 계획 검토): 처음에는 종료 시 `stop`을 보내기로 했으나 뺐다. 이전 패드 세션이
    죽어 드론이 자동착륙 하강 중일 때 키보드 모드를 켰다 끄면 그 `stop`이 공중에서 모터를 끈다.
    사용자 확인(2026-11-03). `stop`은 입력줄에서 직접 보낼 수 있다.
- **계획 검토에서 더한 안전 동작(2026-11-03).** 수신·조종 스레드가 예외로 죽으면 텔레메트리 끊김과
  같이 RC를 멈추고 자동착륙에 맡기며, 지상국을 다시 시작할 때까지 시동·복구·RC 송신을 막는다.
  Ctrl+D 종료도 Ctrl+C처럼 무장 중이면 disarm한다. 같은 포트를 쓰는 지상국이 이미 떠 있으면 시작을
  거부한다. `--listen`은 `connect` 외에는 아무것도 보내지 않는다(트림 재동기화 포함).

## 4. 제약

- **드론에 UDP를 보내는 도구는 한 번에 하나.** 펌웨어는 마지막 발신자에게 텔레메트리를
  보낸다([udp_protocol.md](../../udp_protocol.md)). 수신 전용 모드도 `connect`를 보내므로
  조종 세션과 동시에 켜면 안 된다는 경고를 유지한다.
- 텔레메트리는 20 Hz, raw(`ZIMU`·`ZCAL`)는 별도 데이터그램이다. 수신 스레드는 화면 그리기와
  분리한다.
- 게임패드는 pygame. Linux에서 지금처럼 별도 스레드에서 폴링한다.
- CI의 python 작업은 skip을 실패로 본다. 새 의존성은 `requirements.txt`에 넣고 CI에서 설치된다.
  대시보드 시험은 실제 터미널 없이 돌아야 한다.
- 문서 링크: README·`docs/` 여러 곳과 노션이 스크립트 이름을 가리킨다. 이름이 바뀌면 레포
  문서를 같은 변경에서 고치고, 노션은 main 머지 때 갱신한다.

| | `--keyboard`: 게임패드 없이 명령줄만(RC 송신 없음, `start`·`resume` 차단, 종료 시 `stop`) | `tune_pid.py` |
| | `--listen`: 수신·표시·CSV만, 조종 명령 없음 | `receive_telemetry.py` |

| | `probe <csv>...`: 프로브 응답 분포 | `analyze_probe_response.py` |

기존 옵션(`--no-raw`, `--no-mag`, `--url`, `--out-dir`, `--no-preview`, `--timeout`,
`--no-mp4`, `--label`, `--plot`, `--all`, `--mag-comp` 등)은 새 도구의 같은 모드에서 같은 이름·의미로 받는다.

### 5.2 공유 코드와 보관

- 실행 파일이 아닌 모듈은 `scripts/ground/` 패키지로 모은다: 텔레메트리 스키마·failsafe 이름,
  UDP 링크, 조종 상태 기계(시동·복구·스로틀·트림), 대시보드, 카메라 스트림 파서, 각 분석기 본체.
- `bench_sign_test.py`, `bench_yaw_test.py`, `bench_thrust_ramp.py`, `motor_serial.py`,
  `receive_dual_imu_debug.py`는 `scripts/archive/`로 옮기고 그 README에 용도·전제 조건을 남긴다.
  이 스크립트들의 기존 경고(벤치 스크립트의 WiFi 전환·고정 경로 등)도 함께 옮긴다.
- 옛 이름의 호환용 껍데기 스크립트는 두지 않는다(스크립트 수를 줄이는 것이 목적이다).

### 5.3 ToF 자동착륙 대비

- 고도·failsafe 패널은 고정 필드 목록이 아니라 **텔레메트리 스키마에 있는 필드**로 칸을 만든다.
  필드가 없으면 칸을 숨기거나 `-`로 둔다.
- 고도 칸의 중심은 AGL(바닥까지 거리)이다. 지금의 프로브 필드(`Failsafe_Probe_*`)는
  그 필드가 텔레메트리에 있을 때만 보인다.
- 펌웨어가 failsafe phase 이름·필드를 바꾸면 고칠 곳은 스키마·이름 표 한 곳이어야 한다.

```text

 믹서      RP 1.00  Yaw 1.00  Yaw권한 NORMAL   dG 0.4   Raw 120b/0d
 트림      Roll +0.5  Pitch -1.0     Failsafe -     Faults -
─ 사건 ──────────────────────────────────────────────────────────────
23:15:02 [ARM] 펌웨어 Armed=1 확인 (mag on)

─────────────────────────────────────────────────────────────────────
> pr 0.9▏                         X 시동  △ 복구  R2/L2 스로틀  ? 도움말
```

- 패널 값은 마지막 텔레메트리 샘플과 지상국 상태에서 그린다. 텔레메트리가 끊기면 값을 흐리게
  하고 위 상태줄에 끊긴 시간을 띄운다.
- 지금 `[STATUS]`(1 Hz)·`[DIAG]`(~5 Hz)·`[AUTO-LAND]` 줄로 나오던 내용은 모두 패널로 간다.
  자동착륙 중에는 failsafe 패널을 빨간색으로 키운다(DESCENDING의 매 패킷 값도 패널에서 갱신).
- `[ARM]`·`[RESUME]`·`[FAULT]`·`[WARN]`·`[TRIM]`·`[TH]`·`[STDIN]`·`[LOG]`·`[OK]`·`[ERR]` 같은
  사건 메시지는 사건 영역에 시각과 함께 쌓인다. 문구는 지금 것을 유지한다.
- RC 타임아웃·치명 고장·시동 상태 불일치·텔레메트리 끊김은 위 상태줄에도 강조한다.
- 명령 입력줄은 지금 stdin 명령을 그대로 받는다. `?`는 지금 시작 시 찍던 도움말을 띄운다.
- 화면이 작으면(예: 80×24 미만) 모터·믹서 칸을 접은 배치로 그린다.
- 종료하면 대시보드를 지우고 사건 목록과 로그 저장 경로를 일반 출력으로 남긴다.
- `--listen` 모드도 같은 대시보드를 쓰되 조종 관련 칸(패드 스로틀·트림 조작 안내)을 숨긴다.

## 8. 진행 순서와 검증

- `feat/flow-position-hold` 머지 후 그 위에서 시작한다.
- 동작을 바꾸지 않는 이동(패키지로 옮기기·진입점 만들기)과 화면 교체를 다른 단계로 나눈다.
  단계마다 기존 시험 전체가 통과해야 한다.
- 대시보드는 "상태 → 화면 텍스트" 변환을 순수 함수로 두어 터미널 없이 시험한다(필드 누락,
  failsafe phase별 강조, 작은 화면 배치, 끊김 표시).
- 실기 확인: 벤치에서 `drone_control.py`로 시동·스로틀·트림·명령 입력·자동착륙 표시·종료
  `stop`을 확인하고, `--listen`·`--pad-check`·영상·로그 도구를 한 번씩 실행한다.

- **[Claude 결정] 대시보드 라이브러리는 `prompt_toolkit`.** 고정 레이아웃과 입력줄을 함께
  다루고, 다른 스레드에서 화면 갱신을 요청할 수 있으며, 한글 폭 계산을 한다. 무거운 앱
  프레임워크(`textual`)보다 기존 스레드 구조에 덜 침습적이다. 입력은 파이프 입력으로 시험할 수 있다.
- **[Claude 결정] 옛 이름 껍데기를 두지 않는다**(5.2).
- **[Claude 결정] 화면 갱신은 최대 10 Hz**로 묶는다. 텔레메트리는 20 Hz로 받되 그리기는 따로 한다.
- **[Claude 결정] RSSI는 표시하지 않는다.** 텔레메트리에 없고, 링크 상태는 수신율·드롭률로 보인다.

## 10. 빌더에게 맡기는 것

- `scripts/ground/` 안의 모듈 경계와 이름.
- 패널 색·정렬 같은 세부 모양(6절 배치와 강조 규칙 안에서).
- 기존 시험을 새 모듈 구조로 옮기는 방법(검증 내용은 유지).
