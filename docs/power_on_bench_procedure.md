# 전원 인가 벤치 절차 (첫 호버 전 안전 관문)

`dual_imu_cascade_pwm`의 물리 신호 체인과 자동착륙 경로를 확인하는 절차다.
**프롭 OFF인 Stage A/B부터** 읽고, 조건을 충족한 경우에만 프롭 ON 단계로 간다.
이 문서의 절차 수정은 새로운 벤치·비행 수행이나 통과 판정이 아니다.

### 처음 읽을 때

| 목적 | 현재 읽을 곳 | 확인 범위 |
|---|---|---|
| 전원·모터·부호 검증 | 0·준비 → Stage A → B → C → D | 프롭 OFF 관문 후 제한된 물리 검증 |
| RC 단절·복구 검증 | [Stage E](#stage-e--자동착륙-현재-시간-기반-하강) | 현재 시간 기반 하강, 중단·resume·실제 접촉 시각 |
| 왜 착지 검출기를 쓰지 않는가 | [착지 감지 연구의 현재 상태](failsafe_land_research.md#현재-상태와-기록-해석) | 공중 컷 오라벨 철회, 지면 미검출 관측, 검증 공백 |
| 이전 시험에서 무엇을 보았는가 | [과거 통과 기록](#과거-통과-기록-체크리스트) 및 날짜별 실측 기록 | 당시 펌웨어·기체·조건에 한정된 결과 |

**현재 자동착륙은 `landed=false`, `FS_MAX_MS=3000`이다.** 프로브는 실제
스로틀 딥과 기록을 계속하지만 착지 컷을 결정하지 않는다. 정상 시간 종료는
`Phase` 0→1→3이며, `Phase=2`는 현재 빌드에서 예상하지 않는다. 아래 날짜
기록의 5초·`Phase=2` 성공·0.06 임계·2회 확정은 당시 설정이다.
`010251`을 공중 오판 컷으로 해석한 기록은 철회됐다.

호스트 SIL은 믹서·제어법칙과 모델 안의 상태 전이를 검증한다. 실제 IMU
장착, GPIO→모터 연결, 프롭 방향·추력, yaw 물리 반응과 실제 접촉은 별도
실기 증거가 필요하다. S5/S6b의 yaw 폐루프 수치는 현재도 리포트 전용이다.

**기본은 아래 수동 절차다.** 모터 식별은 Stage A의 `motor_id_single`부터,
비행 펌웨어 부호 검사는 Stage B의 프롭 OFF·텔레메트리 확인부터 시작한다.
`motor_serial.py`는 모터 식별 펌웨어의 시리얼 조작 도구이며, 실제 모터 회전은
USB 통신만으로 검증되지 않는다. 별도 모터 전원과 프롭 제거 조건을 확인한다.

`bench_sign_test.py`·`bench_yaw_test.py`는 기존 고정 환경의 보조 자동화다.
WiFi 전환뿐 아니라 **`trim 0 0`·`start`·주기적 RC**를 자동 실행한다. 부호
시험의 프롭 제거·모터 전원 차단 전제를 코드가 확인하지 않으며, 경로·복귀
SSID도 고정되어 있어 새 환경의 첫 실행 도구로 사용하지 않는다.
`bench_thrust_ramp.py`에는 EOF에서 확인을 통과하고 종료 램프가 지정 `cap_us`를
넘을 수 있는 한계도 있어 초보자 실행 경로에서 제외한다. 실행 조건과 복귀·
판정 출력의 한계는 [자동 벤치 스크립트의 실행 범위](../scripts/README.md#자동-벤치-스크립트의-실행-범위)를 따른다.

2026-07-24의 부호·모터 매핑·회전 방향 결과는 아래 날짜 기록으로 보존한다.

## 0. 핵심 안전 원칙 (읽고 시작)

1. **저스로틀이 안전장치다.** 모든 부호는 최대 권한이 나와도 추력이 약한
   저스로틀에서 검증한다. 부호가 틀려도 위험한 추력이 안 나오는 구간에서만
   확인한다.
2. **부호 검증은 먼저 프롭 OFF·무추력으로 한다.** Tier1 텔레메트리
   `Motor_M1..M4`가 각 모터 PWM(µs)을 실시간으로 보여주므로, 프롭 없이 손으로
   기울이며 **숫자만 읽어** 전체 부호 체인을 확인할 수 있다. 프롭 ON은 그 숫자
   대로 추력이 나오는지 저속으로 확인하는 단계다.
3. **킬·페일세이프 경로를 프롭 돌리기 전에 검증하고, 손 닿는 곳에 둔다.**
   `stop` 명령, 마지막 유효 RC 이후 500ms 초과 시의 컷/하강 분기, 과도 기울기 컷, 그리고
   **배터리 물리 분리**(최종 킬). 배터리 커넥터를 즉시 뽑을 수 있게 준비.
4. **손 위치:** 기체 **프레임(암/센터)**만 단단히 잡는다. 손가락·머리카락·
   옷·케이블을 4개 프로펠러 디스크에서 전부 치운다. 보안경 착용.
5. **역할 분리:** 가능하면 한 명은 기체를 잡고, 한 명은 키보드/패드. 혼자면
   disarm을 한 손에 두고 시작.
6. **틀리면 밀어붙이지 않는다.** 어떤 모터가 "내려가야 하는데 올라간다" →
   **즉시 stop**, 원인 수정, 재검증. 스로틀을 올려 "되게" 만들려 하지 말 것.
7. **펌웨어의 mag 융합 부팅값은 OFF, 지상국의 조종자 기본 선택은 ON이다.**
   `control_dualsense.py`는 무장 전에 선택을 보낸다. `--no-mag` 또는 stdin
   `mag off`로 끌 수 있으며, `[STATUS]`의 `Mag=0|1`은 보드의 실제 상태다.
   선택과 적용을 혼동하지 않는다.

   [BMM350 벤치 문서](bmm350_yaw_bench_test.md)에는 2026-07-27 검증과
   **2026-08-04 hard/soft-iron 변경 후 모터 간섭 재검증** 기록이 있다.
   이는 당시 방위·배터리·환경에서의 결과다. 새 장착·배선·캘리브레이션이나
   다른 배터리 조건까지 검증한 것으로 읽지 않는다. 자이로 단독의 저속 회전
   관측 한계와 자기장 교란을 함께 고려하고 실제 `Mag_Enabled`·heading을 기록한다.

전류 제한 전원(랩 PSU, 예: 5A 리밋)이 있으면 폭주 시 피해를 줄인다. 없으면
배터리로 하되 저스로틀 원칙을 더 엄격히.

## 1. 준비

- 기체를 안정된 곳(또는 손)에 두고, 프로펠러 **제거** 상태로 시작.
- 텔레메트리 모니터 실행:
  ```bash
  python scripts/control_dualsense.py
  ```
  확인할 필드: `Calibration_OK`, `Armed`, `angleX/Y/Z`,
  `Motor_M1..M4`, `PID_Loop_Hz`, `TgtRate_Roll/Pitch/Yaw`, `Yaw_Hold`,
  `Mag_Enabled`, `Failsafe_Phase`, `Trim_Roll/Pitch`, `Fault_*`,
  `Mixer_RP_Scale`, `Mixer_Yaw_Scale`, `Mixer_Collective_US`,
  `Yaw_Authority_State`.
- 모터 물리 위치 라벨(펌웨어 핀 매핑):

  | 텔레메트리 | GPIO | 위치 | 프롭 방향(설계) |
  |---|---|---|---|
  | `Motor_M1` | 4 | **FL** 전-좌 | CW |
  | `Motor_M2` | 5 | **RR** 후-우 | CW |
  | `Motor_M3` | 6 | **FR** 전-우 | CCW |
  | `Motor_M4` | 7 | **RL** 후-좌 | CCW |

- RC 링크(무장 시 500ms 워치독을 먹여야 함): `control_dualsense.py`(게임패드)
  로 arm/disarm + 스틱 중앙=수평 목표(target 0)를 스트리밍하는 것을 권장.
  패드가 없으면 임의 UDP 송신기로 `rcr <seq> 0 0 0`을 **≥5Hz**로
  흘려보낸다. 기존 `rc`도 워치독 급이와 벤치 도구 호환용으로 남아 있지만,
  yaw 각도 필드는 `yaw 1` 오버라이드에서만 사용한다.
- ⚠️ **게임패드는 USB로 연결한다.** 블루투스 패드는 노트북의 WiFi와 무선부를
  공유해 업링크를 수백 ms씩 막고, RC 타임아웃으로 자동착륙을 유발한다.
  절전(서스펜드)도 끄고, 무장 전 링크 체크리스트를 따른다 →
  [ground_station_link.md](ground_station_link.md)

## 2026-08-18 저스로틀 yaw 권한 변경의 실기 게이트

이 절차는 호스트 SIL과 ESP32-S3 compile을 통과한 뒤, **별도 업로드 승인을
받았을 때만** 아래 순서로 진행한다. 2026-08-18 문서 갱신 시점에는 아직 보드
업로드·모터 구동·테더 비행을 하지 않았으므로 다음 네 단계는 모두 미확인이다.

1. **프롭 제거:** 모터 4개의 범위·위치·roll/pitch/yaw 부호를 다시 확인하고,
   `stop`·과도 기울기의 즉시 컷과 RC 500ms timeout 동작을 먼저 통과시킨다.
2. **손 파지·저출력:** `1200→1270→1300µs` 순서로 올린다. 먼저 수동 yaw 스틱
   명령에 대한 회전 방향과 응답 확인을 끝낸다. 그다음 yaw 스틱을 놓아 중립으로
   되돌리고 지상국 명령이 `yaw_rate=0`인지 확인한 뒤에만, 손으로 지속적인 강제
   yaw 외란을 준다. 이 외란에서 yaw가 먼저 제한될 때
   `Mixer_Yaw_Scale<1`, `Mixer_RP_Scale≈1`이어야 하고, 지속 제한이면
   `Yaw_Authority_State`가 `NORMAL(0)→LIMITED(1)`로 들어가
   `TgtRate_Yaw=0`을 명령해야 한다. RP scale이 먼저 떨어지거나 비틀림을
   증폭하면 즉시 `stop`한다.
3. **테더 호버:** 1300µs 부근에서 30초 기록한다. 같은 날 변경 전 기준 대비
   roll·pitch RMSE 증가는 각각 20% 이내, 절대 roll RMSE≤5°,
   pitch RMSE≤4°여야 한다.
4. **지상 이륙→호버→착륙 3회:** 착륙 말단 roll·pitch가 각각 15° 미만,
   전체 샘플의 99% 이상에서 `Mixer_RP_Scale≥0.95`, LIMITED 뒤
   `|TgtRate_Yaw|=180dps`가 0.5초 이상 연속하지 않아야 한다.
   `Fault_RC`, `Fault_IMU1/2`, `Fault_Disagree`, `Fault_Attitude`와 예기치 않은
   failsafe도 0건이어야 한다.

> **2026-10-14 게이트 결과 기록 (main 머지 전).** 1–3단계는 시험 수행자가
> 2026-08-19 비행 전에 수행했다고 확인했다. 다만 그때의 수치(3단계의 RMSE 비교
> 등)는 레포에도 노션에도 남아 있지 않다. 4단계는 2026-08-19의 다섯 사이클
> (`031801` #1, `032012` #1–3, `032537` #1)로 통과했다. 착륙 말단 2초 최대
> roll/pitch는 11.71°/11.45° 이하, 사이클마다 `Mixer_RP_Scale≥0.95`가 99%
> 이상, 고장·예기치 않은 failsafe 0건이고, LIMITED 뒤 `|TgtRate_Yaw|=180dps`가
> 이어진 구간은 없었다. `032012` #2에서는 공중에서 LIMITED가 실제로 발생했다.
> 같은 날 `020246`은 착륙 말단 roll이 −19.9°였다. 노션 기록은 이 비행을
> 다섯 사이클과 별도의 직전 비행으로 다룬다.
> 머지 직전 지상국의 무장 확인에서 deadline 검사를 성공 판정보다 앞으로
> 옮기고, 패킷 수신 시각이 아니라 판정 시각으로 검사하게 했다. 마감 뒤에
> 도착하거나 마감 뒤에 판정된 `Armed=1`은 이제 무장 성공이 아니라 시간 초과로
> `stop`을 보낸다. 이 수정은 지상국 쪽만 바꾸며 실기 검증은 하지 않았다.

현행 비행 검증 구성에는 사용 가능한 **optical flow 기반 수평 위치 보정이
없다.** 따라서 중립 스틱에서도 생기는 수평 표류는 조종자가 수동으로 상쇄해야
한다. 이 수동 위치 보정 입력 자체는 위 통과 기준의 실패가 아니며, yaw heading
오차도 RP 자세 보존보다 낮은 우선순위다. 다만 표류 때문에 테더·장애물에
접근하면 즉시 중단한다.

## Stage A — 프롭 OFF: ESC 아밍 · 회전 방향 · 매끄러움

**목적:** 각 ESC가 아밍되고 매끄럽게 돌며, 회전 방향이 설계와 맞는지. 회전
방향은 3상 배선으로 정해지므로 PWM 주파수와 무관하다(그래서 50Hz 진단
펌웨어로 확인해도 유효).

1. 먼저 [`motor_id_single`](../firmware/diagnostics/motor_id_single/motor_id_single.ino)
   진단 펌웨어로 개별 모터를 식별한다. 프롭 OFF·기체 고정 상태에서
   시리얼 `1`~`4`로 **한 번에 한 모터만** 선택한다. 자동 시작이 없고 기본
   1120µs·상한 1250µs이며 `0`/`s`로 정지한다. 알 수 없는 키도 전체 정지한다.
2. 각 모터 벨(bell)에 방향 표식을 하고, 출력된 모터 번호·GPIO·예상 위치가
   실제로 도는 모터와 맞는지 확인한다. `motor_serial.py`를 쓸 때는 지정
   시리얼 포트를 먼저 확인한다.
3. **위에서 내려다보며** FL(M1)·RR(M2)=**CW**, FR(M3)·RL(M4)=**CCW**인지
   각각 확인한다. 떨림/역회전/코깅 없이 매끄럽게 돌고 아밍음이 정상인지 기록한다.

**방향이 틀리면:** 그 모터의 3상 중 **아무 두 선을 교체**하고 재확인.
**틀린 방향으로 프롭 달고 진행 금지** — 추력이 아래로 향하거나 yaw 반작용이 반대가 된다.

별도의 [`motor_pwm_bench`](../firmware/diagnostics/motor_pwm_bench/motor_pwm_bench.ino)는
개별 식별 뒤 4모터의 동시 램프를 확인하는 진단 펌웨어다. **부팅 7초 뒤
자동으로 4모터를 1300µs(스로틀 범위의 30%)까지 올린다.** 실제 추력이 최대의
30%라는 뜻은 아니다. 프롭 OFF·기체 고정·모터 전원 정지 수단을 갖춘 경우에만
사용하며 개별 모터를 식별하는 도구로 쓰지 않는다. Python 자동화 도구
`bench_thrust_ramp.py`와도 별개다.

## Stage B — 비행펌웨어, 프롭 OFF: 킬 경로 + **부호 전체(무추력) 검증**

`dual_imu_cascade_pwm`를 플래시. **프롭은 아직 OFF.** ESC가 이 펌웨어의 400Hz
PWM에서도 아밍되는지 먼저 확인(부팅 시 `stopMotors`로 정지 신호 유지).

### B-1. 부팅/상태
- 시리얼에 `[CALIB] OK`. 텔레메트리 흐름 정상, `Armed=0`.
- `gains` 명령의 값을 주력 펌웨어 선언값과 비교한다. 현재
  **Ki_Rate_Roll/Pitch = 0.0500**이며, 실행 중 덮어쓴 이득이 있으면 함께 기록한다.

### B-2. 킬·페일세이프 경로 검증 (프롭 OFF)

RC 스트림을 켜고 `start` 후 `th 1150`을 유지한다.

1. **stop:** `Motor_M1..M4=1000`, `Armed=0`을 확인한다.
2. **유효 호버 추정치 없음:** 새 무장 세션에서 `Hover_Valid=0`을 확인한 뒤
   RC를 끊는다. 마지막 유효 RC부터 **500ms를 초과한 다음 제어 tick**에
   `Fault_RC=1`, 모터 1000, `Phase=0`이 되고 시리얼에는
   `[FAULT] RC TIMEOUT -> CUT (NO HOVER EST)`가 한 번 나와야 한다.
   20Hz 텔레메트리에는 전송 주기·지연만큼 늦게 보일 수 있다.
3. **유효 추정치가 있는 지상 스로틀:** 추정치가 이미 유효해도 RC 단절 시
   현재 스로틀이 `FS_GROUND_CUT_MAX_US` 이하이면 `GROUND CUT`으로 즉시
   컷하고 `Phase=0`이다. 두 분기를 같은 시리얼 메시지로 기대하지 않는다.
4. **오버틸트:** 프롭 OFF에서 다시 무장하고 `SAFETY_ANGLE`을 **초과**하도록
   기울인다. `Fault_Attitude=1`, 모터 1000을 확인한다.
5. **물리 킬:** 배터리 커넥터로 모터 전원을 분리하는 동작을 확인한다.

정지한 기체도 수평·1g·스로틀 **1150 초과** 조건을 만족하면 호버 후보 시간을
누적한다. 손 파지·책상 고정 상태의 `Hover_Valid=1`은 실제 호버의 증거가 아니다.
그 상태에서 1150을 넘긴 채 RC가 끊기면 현재는 최대 3초의 하강 경로에 들어가
모터가 계속 돌 수 있다. 프롭 ON 부호 벤치는 1150 이하를 유지한다.
자동착륙의 논리 검사는 먼저 프롭 OFF로, 실제 호버·하강은 Stage E로 구분한다.

### B-3. 부호 체인 검증 — 무추력, 텔레메트리 숫자만 읽기 ★
`start` + `th 1150`, rc 스트림 중앙(target 0). 기체를 손으로 살짝 기울이며
**`Motor_M1..M4` 숫자 변화**를 본다. 관례에 의존하지 않는 **불변식**:

> **누른(아래로 내린) 쪽의 모터가 반드시 올라가야 한다** (그 쪽을 다시 밀어
> 올리려고). 반대로 **든(위로 올라간) 쪽 모터가 올라가면 부호 반전 → 즉시 stop.**

| 손 동작 | 올라가야 하는 모터 | 내려가야 하는 모터 | angle 확인 |
|---|---|---|---|
| **우측을 아래로**(roll) | M2(RR), M3(FR) = 우측 | M1(FL), M4(RL) | `angleX`가 한 방향으로, 수평복귀 시 0 |
| **좌측을 아래로** | M1(FL), M4(RL) = 좌측 | M2(RR), M3(FR) | `angleX` 반대 부호 |
| **기수를 아래로**(pitch) | M1(FL), M3(FR) = 앞 | M2(RR), M4(RL) | `angleY` 한 방향 |
| **꼬리를 아래로** | M2(RR), M4(RL) = 뒤 | M1(FL), M3(FR) | `angleY` 반대 부호 |

- 각 방향에서 **기울인 직후 순간**의 모터 반응을 읽는다(적분기가 쌓이기 전,
  P+D 지배 구간). 검사 사이에 수평으로 되돌려 `th 1050` 등으로 잠깐 낮추면
  적분기(>1100에서만 누적)가 리셋된다.
- `TgtRate_*` 텔레메트리도 함께: 우측 아래로 기울이면 `TgtRate_Roll`이
  복귀 방향으로 명령되는지.

**여기서 roll/pitch 부호 체인 전체(실IMU 방향 포함)를 추력 위험 없이
확정한다.** SIL이 시뮬로 확인한 것을 실하드웨어로 닫는 단계.

**틀리면(든 쪽이 올라감):** stop. 원인 후보 — IMU 장착 방향/축 부호, 믹서 부호,
outer/inner 부호. 텔레메트리 `angle` 부호가 먼저 맞는지 보고(센서 문제 vs 믹서
문제 구분), 수정 후 재검증.

### B-4. 1kHz IMU raw 전송 부하 확인 — 무장 해제 상태에서만

1. `Armed=0`인 상태에서 `control_dualsense.py`를 시작한다. raw 스트림은
   기본 ON이므로 `raw on`을 입력하지 말고, 연결 후 `[STATUS]`의
   `Raw=<batches>b/<dropped>d`에서 배치 수가 증가하는지 확인한다.
2. [현행 텔레메트리](udp_protocol.md)의 `RC_Dropped_Pkts`와 `PID_Loop_Hz`,
   `[STATUS]`의 생산자 `dropped`를 나란히 관찰한다.
3. `RC_Dropped_Pkts` 증가 양상과 `PID_Loop_Hz`가 둘 다 나빠지지 않고,
   `Raw`의 생산자 dropped가 증가하지 않는 것을 확인한 뒤에만 무장한다.
   하나라도 나빠지면 `raw off` 후 원인을 조사하며 무장하지 않는다.
4. 기록이 끝나면 지상국을 정상 종료한다. 원본
   `logs/imuraw_<timestamp>.bin`과 자동 변환된 같은 이름의 `.csv`가
   남고, 종료 요약의 레이트·무선 유실·생산자 드롭을 확인한다.

2026-07-30 무장 해제 벤치 실측(219배치, 10,950샘플)은
`average_sample_rate_hz=999.999`, `wireless_lost_batches=0`,
`producer_dropped=0`이었다.

## Stage C — 프롭 ON, 손 파지, 저속: 추력 방향 + yaw 부호

Stage B에서 부호가 **숫자로** 확인됐으므로, 이제 프롭을 달고 **숫자대로 추력이
나오는지** 저속으로 확인한다. 프레임을 단단히 잡고 시작.

### C-1. 추력 방향 (매우 저속)
- 프롭 장착. `start`, `th 1080`부터(겨우 도는 수준). rc 중앙.
- **기체에 위쪽 추력이 생기는지** 확인한다(기체가 위로 뜨려 하며 지지에
  실리는 무게가 줄어든다). 아래쪽 추력이면 프롭 방향/장착을 점검한다 → stop, Stage A로.
- 스로틀은 **손 파지 중 ~1150 이하 유지.** 틸트는 작게.

### C-2. 틸트 복원 (물리)
- 저속 유지 상태에서 Stage B-3의 각 방향으로 **작게** 기울여, 텔레메트리에서
   올라간 모터가 실제로 그 쪽을 **밀어 올리는** 반작용이 손에 느껴지는지.
   숫자(B-3)와 물리(C-2)가 일치해야 한다.

### C-3. yaw 부호 — SIL S5 미해결 항목 닫기 ★
1. 먼저 `stop`하고 `Armed=0`을 확인한다. **`yaw 1`을 `start`보다 먼저**
   보내고 다시 시동한다. `yaw 1`은 시동 중에는 거부되고 무장 해제 엣지에서
   자동 해제되는 비행별 벤치 opt-in이다.
2. `yaw 1` 오버라이드에서 기체를 위에서 볼 때 한 방향으로 **살짝 비틀면**,
   컨트롤러가 **그 비틀림에 저항**(복원)하는 반작용을 내야 정상이다.
   **비틀림을 키우면(증폭) yaw 부호 반전.** 불변식: **"내가 준 비틀림을
   거스른다."**
3. `yaw 0`을 보내 자동 모드로 전환한다(`yaw 0`은 시동 중에도 수락된다).
   `control_dualsense.py`의 yaw 스틱을 밀어 명령 방향으로 회전하는지,
   `TgtRate_Yaw`와 실제 회전 방향이 일치하는지 확인한다. 최대 명령은 지상국
   상수 `YAW_RATE_MAX_DPS = 90.0`에 따른 ±90dps다.
4. 스틱을 놓으면 회전 중에는 `Yaw_Hold=0`을 유지하고, yaw 각속도가 정착한
   뒤 `Yaw_Hold=1`로 바뀌면서 **멈춘 그 heading을 유지**하는지 확인한다.
   이때 `TgtAngle_Yaw`가 멈춘 heading에서 고정되어야 한다. 회전이 정착하지
   않으면 강제 잠금 없이 rate 모드에 남는 것이 정상이다.
5. 자동 잠금된 상태에서 손으로 기체를 **10dps가 넘도록 빠르게 비튼다.**
   손 파지로 자유 회전과 바운스백 궤적을 직접 보기 어렵더라도 이 검사는
   판정할 수 있다. 외란 중에도 `Yaw_Hold=1`을 유지하고 `TgtAngle_Yaw`가
   고정된 채 원래 heading으로 되돌리려는 복원력이 손에 느껴져야 한다.
   스틱을 실제로 놓는 순간에는 반대 방향 바운스백 오버슛도 없어야 한다.

> **2026-07-30 latching 수정 전/후 판정 기준.** 수정 전에는 잠금 중 외란이
> 10dps를 넘으면 `Yaw_Hold`가 0으로 떨어지고 `TgtAngle_Yaw`가 밀린 새 각도로
> 점프했다. 수정 후에는 `YAW_HOLD_SETTLE_DPS`가 새 잠금의 진입 게이트일 뿐
> 기존 잠금의 해제 조건이 아니므로, 위 5번처럼 손으로 잡은 상태에서도 heading
> 유지와 복원 동작을 확인할 수 있다.

`YAW_RATE_DEADZONE = 3dps`와 `YAW_HOLD_SETTLE_DPS = 10dps`는 벤치 조정용
시작값이다. 4번에서 잠금 진입이 지나치게 이르러 바운스백이 생기면
`YAW_HOLD_SETTLE_DPS`를 낮추고, 프롭 ON 진동에서 새 잠금이 전혀 걸리지 않으면
올린다. 값을 바꾸면 최종값과 관측 근거를 통과 기록에 남긴다.

증폭이면 stop. 원인 — 믹서 yaw 부호 또는 프롭 회전 방향(Stage A). yaw
반작용은 프롭 방향에 의존하므로 Stage A가 선행돼야 의미가 있다.

> SIL S5와 S6b는 yaw 플랜트 반작용 토크 부호가 미해결이라 폐루프 yaw를
> 검증하지 못한다. 자동 잠금과 스틱 해제 후 지속 회전 제거는 이 프롭 ON
> 벤치에서만 확인한다. 관례 추정이 아니라 **실측**이 판정한다.

## Stage D — (옵션) 적분기/트림 관찰

- 저속 손 파지에서 작은 정상 편향에 대한 `Motor_*`/`TgtRate_*` 변화와
  진동을 기록한다. 내부 `iTerm`은 현재 ASCII 텔레메트리에 직접 노출되지
  않으므로 그 값을 화면에서 읽었다고 보고하지 않는다. 실제 적분은 스로틀과
  믹서 포화 조건에도 의존한다.
- 모터 떨림이나 정상 편향이 남으면 이득뿐 아니라 트림·CG·포화·기구 진동을
  함께 조사한다. 이득을 바꿀 때는 변경값과 전후 조건을 기록하며, 손 파지
  반응만으로 자유 비행의 최종 Ki를 확정하지 않는다.
- yaw rate 모드에서도 적분기가 동작하도록 바뀌었으므로 스틱 회전과 해제 후
  yaw 진동이 생기는지 별도로 관찰한다. 진동하면 현재
  `Ki_Rate_Yaw = 0.05`를 낮추고 C-3의 명령 회전·자동 잠금·바운스백 검사를
  다시 수행한다.

## Stage E — 자동착륙: 현재 시간 기반 하강

**진입 조건과 종료 경로를 먼저 구분한다.** 유효 RC가 500ms 넘게 끊겼을 때,
현재 무장 세션의 `Hover_Valid=1`이고 현재 스로틀이 지상컷 하한을 초과해야
`Phase=1` 하강으로 간다. 유효 추정치가 없거나 지상컷 하한 이하이면 Stage B-2의
즉시 컷 경로다. 실제 무장 시 추정기가 초기화되어 이전 비행 값은 재사용하지 않는다.

하강은 `round(Hover_Est) − FS_DESCENT_DELTA_US`를 기준으로 하고 프로브
딥을 추가로 적용한다. **접지 여부와 무관하게 진입 후 3000ms에서 `Phase=3`으로
컷한다.** 그 전에 중단 조건이면 `Phase=4`, 명시적 `resume`이 수락되면
`Phase=0`으로 복귀한다. `Phase=2`는 현재 코드에서 예상하지 않는다.

코드 정본은 [주력 펌웨어](../firmware/flight/dual_imu_cascade_pwm/dual_imu_cascade_pwm.ino)의
`pid_task`·`resumeRefusalReason`과 [failsafe_land.h](../firmware/flight/dual_imu_cascade_pwm/failsafe_land.h)다.
상수 변경 이력은 아래 날짜 기록, 현재 프로토콜은 [udp_protocol.md](udp_protocol.md)를 본다.

### 관측 도구와 raw 기록

Stage E에는 `control_dualsense.py` 하나만 띄운다. UDP 발신자가 달라지면
펌웨어의 텔레메트리 목적지도 바뀌므로 다른 모니터를 동시에 띄우지 않는다.
`[DIAG]`·`[AUTO-LAND]`와 CSV, 같은 세션의 1kHz raw 파일을 보존한다.

raw는 기본 ON이다. **B-4의 부하 확인을 먼저 수행**하고 모든 단계에서
`RC_Dropped_Pkts`·`PID_Loop_Hz`·raw 손실을 본다. 하강 진입 때 RC가
끊겼어도 이후 RC가 복구될 수 있고 `stop`·`resume`도 상향 전송이 필요하므로,
하강 중 raw가 RC와 전파를 다툴 수 없다고 가정하지 않는다.

20Hz CSV는 프로브의 마지막 응답·누적 카운터를 읽는 데 쓰고, 1kHz raw는
딥 내부 파형과 접촉 후보를 분석하는 데 쓴다. 한 tick인 `EVALUATE`·`BLOCKED`
상태는 CSV에서 누락될 수 있어 그 행 수를 전체 이벤트 횟수로 세지 않는다.
결측·부하 문제가 있으면 시험을 중단하고 프롭 OFF 상태에서 raw OFF 비교로
원인을 분리한다. **20Hz CSV나 SIL로 실기 1kHz 파형의 미확인을 대체하지 않는다.**
2026-07-30의 999.999Hz·손실 0 기록은 그 무장 해제 시험 조건에 한정된다.

### E-0. 호버 추정: 논리 검사와 실제 호버를 구분

먼저 프롭 OFF에서 추정기 누적·초기화 경로를 확인한다. 실제 시험에서는
제한된 저고도 조건에서 실제 호버를 유지하며 `Hover_Est`·`Hover_Valid`를 기록한다.
roll/pitch 절댓값이 10° **미만**, `|accel|`이 1g±0.05g 이내, 스로틀이
1150 초과인 후보 시간의 누적이 1.5초에 이르면 유효해진다. 후보가 아닌 동안은
누적과 갱신이 멈추며 기존 값은 보존된다. 유효 샘플에서는 3초 시정수 LPF로 갱신한다.

유효 전에는 실제 비행의 RC를 의도적으로 끊지 않는다. 손이나 고정구로 지지한
상태에서 얻은 값을 실제 호버 추력으로 간주하지 않는다. 배터리·기체 구성과
실제 호버 추정치, 현재 스로틀, 지상컷 하한의 여유를 함께 기록한다.

### E-1. 상태 전이와 시간 종료 (프롭 OFF부터)

프롭 OFF에서 유효 추정치를 만든 같은 무장 세션으로 RC 단절을 시험한다.
`Phase` 0→1, `Fault_RC=1`, 하강 기준 스로틀과 주기적 딥을 확인한다.
중단·resume이 없으면 **하강 진입부터 약 3초에 1→3**, 모터 1000,
`Armed=0`이어야 한다. 마지막 RC부터의 500ms 초과 대기와 하강 3초를 별도로 잰다.
텔레메트리 시각의 해상도·지연도 함께 기록한다.

`Phase=2`나 다른 시간 예산이 보이면 먼저 보드의 펌웨어 버전과 원본 패킷,
스키마를 확인한다. 검출기 임계를 현장에서 바꾸어 합격시키지 않는다.

### E-2. 중단 경로 (프롭 OFF)

프롭 OFF에서 `Phase=1`을 만든 뒤 `stop`으로 `Phase=4`·모터 1000을
확인한다. 오버틸트 경로도 **프롭 OFF로만** 의도적으로 재현한다.
두 IMU 사용 불가·중재 불가 등의 고장은 native/host 시험 결과와 실제 보드
재현 여부를 구분한다. 프롭 ON 하강 중 기체를 강제로 크게 기울이는 절차로
이 항목을 검증하지 않는다.

### E-2a. 명시적 `resume` 복구 (프롭 OFF부터)

1. `Phase=1`에서 RC 스트림만 복구한다. **RC만으로 `Phase=0`이 되면 실패**다.
2. 유효 RC가 최근 500ms 이내이고 자세·IMU·호버 유효 조건과 누적 예산을
   만족할 때 `resume`을 보낸다. `Phase` 1→0, `Fault_RC` 1→0,
   `Throttle=round(Hover_Est)`와 정상 스로틀 창 복원을 확인한다.
3. RC를 복구하지 않은 거부 시험은 프롭 OFF로 한다. `rc` 외에 `phase`·
   `tilt`·`imu`·`hover`·`cumulative` 거부가 있으며, 최초 하강 진입부터
   `FS_RESUME_MAX_MS=9000`에 도달하면 `resume`을 거부한다.
   이 값은 **누적 시점 이후 resume 거부 조건**이며 그 순간의 강제 컷 타이머가 아니다.
   현재 하강이 끝나거나 별도 중단 조건이 생길 수 있으므로 거부 이후 상태를
   무조건 계속 `Phase=1`이라고 기대하지 않는다.

`resume`은 호버 추정 스로틀과 조종 명령권을 복구한다. **이미 생긴 하강속도나
고도를 복구하지 않는다.** 실제 비행에서의 복구는 별도 조종 대응과 고도 여유가
필요하며, 이 프롭 OFF 시험으로 검증되지 않는다. 하강 중 `start`는 복구 수단이 아니다.

### E-3. 프로브 구동과 기록 (프롭 OFF부터)

프로브는 진입 후 최소 하강 시간을 기다린 뒤 400ms마다 120ms 딥을 요청한다.
명목 딥은 `round((Hover_Est−1000)×0.118)`에 하한·상한을 적용한 값이다.
`Hover_Est=1340`이면 40µs지만 시험마다 실제 추정치와 출력 딥을 기록한다.

`Failsafe_Probe_State`·`NoResponse`·`Response_G`를 확인한다. 무반응 카운터가
4에 도달하고 1g 조건을 만족해도 **현재는 `Phase=2`로 컷하지 않는다.**
`UNAVAILABLE`·`BLOCKED`는 딥 가용성·전달 문제의 진단이다. 손 파지나 고정구의
반응을 공중 분포로 취급하지 않는다. 프롭 OFF는 PWM 적용의 논리 증거이고,
실제 추력 딥 전달은 별도 물리 측정이 필요하다.

### E-4a. 프로브 연구용 기록 — 자동 컷 복귀 조건과 구분

현재 컷 판정은 연구용 응답 분포에 의존하지 않는다. 기존 프로브의 지면
미검출과 공중 라벨 철회는 [착지 감지 연구](failsafe_land_research.md)를 따른다.
SIL의 옛 80 N/m·지면 0.05g 수치를 현행 실제 착륙의 합격 기준으로 쓰지 않는다.

- 실제 접지 전후를 독립적으로 라벨하고, 실제 착륙면·기체 구속 여부·
  `Hover_Est`·실제 딥·배터리·기울기·손실을 함께 기록한다. 무게추로 누른
  벤치와 자유 착륙, 서로 다른 딥 크기의 응답은 같은 분포로 합치지 않는다.
- 접지 로그뿐 아니라 **접지 없는 하강의 반복 음성 대조군**이 필요하다.
  손 파지·매달기에는 외력이 작용하므로 자유 하강 대용이 아니다. 기존
  `023904`의 접지 전 프로브 2회만으로 공중 오검출률을 확정하지 않는다.
- 알려진 라벨 구간의 CSV를 `scripts/analyze_probe_response.py`로 분석한다.
  한 CSV 안에 접지 전후가 섞였으면 파일 전체에 `ground`나 `air`를 붙이지
  않는다. 도구가 출력한 이벤트 수와 20Hz 관측 한계를 확인한다.
- 응답이 겹친다고 딥 비율·제어 창을 즉시 키우지 않는다. 현재 호버 부근에서는
  모터 하한·자세 차동 때문에 요청 딥이 잘릴 수 있다. `BLOCKED`의 원인과
  전달률을 먼저 확인하며 임계 변경·자동 컷 복귀는 별도 설계와 검증 사안이다.

### E-4. 실제 저고도 하강 — 접촉과 컷을 따로 기록

E-0~E-3의 프롭 OFF 검사와 선행 물리 검증을 마친 뒤, 제한된 실제 시험 조건에서
실제 호버·하강·접촉·컷을 구분해 기록한다. 접지 판정 성공인 `Phase=2`를
목표로 튜닝하지 않는다. **정상 시간 종료는 `Phase=3`**이다.

확인할 값은 진입 높이의 측정 근거, `Hover_Est`, 하강 스로틀·딥, 접촉 시각의
독립 근거, 컷 시각, 접촉 후 모터 지속 시간, 접지 전 컷 여부, 자세·위치 변화다.
거리/광류 MSP 수신·기록 코드는 구현됐으나 최근 시험에서 신선한 값은 확보하지
못했다([현재 상태](current_status.md)). 고도·수평 위치 제어에는 사용되지 않는다.

### E-4b. 낮은 스로틀 진입의 적분 조건 (프롭 OFF)

`Hover_Est=1250`인 시험에서 기준 하강 스로틀은 1190이다. 이것만으로 적분기가
리셋되지는 않는다. 실제 제어 tick의 스로틀이 **1100 이하일 때** 세 적분기를
리셋하고, 그보다 높으면 믹서 포화 조건에 따라 누적·보존한다. 현재 스로틀
1250과 호버 추정치 1250은 같은 값이라고 가정하지 않는다. 내부 적분기 값은
현행 CSV에 없으므로 native 시험과 보드의 모터 반응 관측을 구분한다.

### E-4c. 하강 중 `th`의 지속 효과 없음 (프롭 OFF)

`Phase=1`에서 `th` 명령을 보내도 하강 블록이 매 tick 기준 스로틀·딥과
제어 창을 다시 설정하는지 확인한다. 파서 자체가 `th`를 거부하는 구현은
아니므로 단일 텔레메트리 스냅샷에 원자적 불변식을 기대하지 않는다.
실제 모터 출력이 지속적으로 임의 스로틀을 따르는지는 native 검사와
시간열로 확인한다. 이 시험을 높은 스로틀의 프롭 ON 실험으로 대체하지 않는다.

### E-5. 고도·시간 예산 평가 (미검증 조건 확장 전)

`FS_MAX_MS=3000`은 실제 접지를 확인하지 않는 시간 예산이다. 과거의 평균
가속도 1.24m/s²에 등가속식을 적용한 **3초=5.60m는 외삽**이며 실측 커버
고도나 시험 허용 범위가 아니다. 프로브 배치를 위한 `static_assert`의
2720ms 초과 조건도 접지·고도 안전성을 증명하지 않는다.

고도를 자동으로 1→2→3m 올리거나 접지 전 컷을 보고 시간 상수를 즉시 늘리지
않는다. 앞 단계에서 얻은 실제 접촉·컷·하강속도 근거와 복구 가능성을 검토해
다음 시험 범위를 정한다. 바람에 대한 위치 유지 기능은 없으며, 접지 전
타임아웃 컷과 접지 후 모터 지속이 모두 가능한 한계로 남는다.

`FS_GROUND_CUT_MAX_US=1150`이 지키는 범위는 "조종자가 1150을 넘기지 않는
동안"뿐이다. 프롭 ON에서 `th 1200`으로 작업하면 링크 단절 시 자동착륙으로 간다.
3차 감사 S1이 손 파지에 대해 지적한 것과 같은 구조이며, **벤치 스로틀을 1150

### 지면 프로브 응답 — 완전 지지

같은 하강에서 자세도 무너졌다(Roll 오차 최대 22.1°, `gZ` −79~+45dps,
CW−CCW −398~+269µs). 모터는 1000/1900에 닿지 않았고 하강 권한 창에도
380샘플 중 4회만 닿았으므로 **권한 부족이 아니다** — 실내 재순환이 유력하다.

**현재 조치:** 프로브를 **판정에서 완전히 뺐다.** 자동착륙은 시간 기반
하강이며 `FS_MAX_MS` 뒤 백스톱이 자른다. 공중 컷 위험이 0이고, 대가는 접지
후 프롭이 도는 시간이다. 프로브는 계속 돌며 텔레메트리로만 기록된다.

`FS_MAX_MS`는 **5000 → 3000ms**로 줄였다. 2026-08-01 실측(접지 충격 임펄스
적분 → 접지 속도, 등가속 역산)에서 평균 하강 가속도 a≈1.24 m/s²이고 최고
시험 고도가 1.86m(`023904`, 접지 1.76s)였다. 3.0s는 5.60m를 덮어 최고 시험의
3배이고, `static_assert` 하한 2720ms보다 크다(2.5s는 컴파일 실패).

⚠️ **SIL이 이 실패를 재현하지 못한다.** R1은 백색잡음 σ=0.08g에서 100회 중
0회 오판으로 통과한다. 프로브 LPF 차단이 약 4.8Hz라 백색잡음은 걸러지지만
실제 교란은 0.5~3Hz에 몰려 있어 그대로 통과하기 때문이다. 잡음 모델을
대역제한으로 바꾸기 전까지 SIL은 비행에서 깨질 설계를 계속 통과시킨다.

전체 분석과 근본 개선 방향은 **[failsafe_land_research.md](failsafe_land_research.md)**.

**그때까지의 운용 제약: 실내 저고도 자동착륙을 신뢰하지 않는다.**
