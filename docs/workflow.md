# 작업 순서와 인수인계

## 처음 참여했다면

1. [현재 상태](current_status.md)에서 가능한 기능과 남은 관문을 읽는다.
2. [하드웨어 구성](hardware_configuration.md)과 [프로젝트 개요](project_overview.md)로
   센서→추정→PID→믹서→ESC 흐름을 확인한다.
3. [펌웨어 카탈로그](firmware_catalog.md)에서 작업할 스케치를 고른다.
   주력·보류·진단·보관 코드를 구분하고 진단 스케치의 자동 구동 여부를 확인한다.
4. [벤치 절차](power_on_bench_procedure.md)의 프롭 OFF 단계부터 시작한다.
   단일 모터 식별은 `motor_id_single`을 사용한다.

## 한 번의 작업 흐름

| 단계 | 할 일 | 남길 것 |
|---|---|---|
| 작업 선택 | 해결할 현상·완료 조건·담당자와 시험 구성을 정한다 | 한 문장 목적, 펌웨어·지상국 커밋, 기체 조건 |
| 재현·수정 | 기존 로그나 테스트로 현상을 확인하고 해당 경로를 수정한다 | 실패 근거와 diff. 상수·명령 변경은 프로토콜 정본에 반영 |
| 코드 검증 | Python 검사·네이티브/SIL·Arduino 빌드를 실행한다 | 명령, 성공/실패, 건너뛴 항목과 원인 |
| 벤치 | 모터 식별·부호·시동/정지·링크 상실을 순서대로 확인한다 | 해당 Stage 체크, 시리얼·CSV·raw 로그 |
| 제한된 실기 시험 | 앞 단계의 조건을 충족한 구성으로 수행한다 | 조종자·관찰자, 기체·배터리·테더, 접촉 라벨·영상 |
| 분석·인수인계 | 관측·해석·미확인을 구분하고 다음 한 가지 작업을 정한다 | 결과, 재현 방법, 남은 문제, 다음 담당자 |
| 통합·문서 | 변경 검토 후 통합하고 관련 설명형 문서와 노션 상태를 갱신한다 | 통합된 커밋, 기록 링크, 완료 체크와 결과 한 줄 |

## 검사 명령

저장소 루트에서 의존성이 준비된 Python 환경을 사용한다.

```bash
python -m py_compile scripts/*.py
python tools/check_repo_layout.py
python -m unittest discover -s tools -p 'test_*.py' -v
arduino-cli compile --warnings all --fqbn esp32:esp32:esp32s3 \
  --build-path /tmp/zetin-flight-build firmware/flight/dual_imu_cascade_pwm
git diff --check
```

Python 패키지는 [requirements.txt](../requirements.txt), 보드 코어·라이브러리는
[펌웨어 가이드](../firmware/README.md)를 따른다. 전체 CI는 주력·보류 후보와
진단 스케치를 모두 컴파일한다. 네이티브 성공은 Arduino 전처리·보드 라이브러리
빌드 성공을 대신하지 않는다.

## 지상국 운용 순서

1. 게임패드는 USB로 연결하고 `gamepad_probe.py`로 입력을 확인한 뒤 종료한다.
2. `Drone_Tuning`에 연결하고 `control_dualsense.py` 하나만 실행한다.
3. 시동 전에 센서·고장·트림·자기계 상태와 로그 기록을 확인한다. 명령 전송
   배너만 보고 무장 성공으로 판단하지 않는다.
4. 수동 정지는 `stop`, 링크 상실 시 동작과 명시적 복구는
   [지상국 안내](../scripts/README.md)를 따른다. 연결 복귀가 조종권 복귀는 아니다.
5. 접지 후 무장을 해제하고 종료 시 CSV·raw 파일 생성과 디코드 결과를 확인한다.
   분석할 때는 `flight_log_*.csv` 경로를 명시한다.

자동 벤치 스크립트의 고정 환경·자동 시동·입력 확인·스로틀 제한 문제는
[실행 범위](../scripts/README.md#자동-벤치-스크립트의-실행-범위)를 먼저 읽는다.

## 기록 양식

```text
날짜 / 담당 / 목적:
펌웨어 커밋 / 지상국 커밋 / 실제 업로드 확인 방법:
보드·센서·모터·프롭·배터리 / 테더·고정 조건:
변경한 한 가지와 예상 결과:
실행 명령 / 통과·실패·미실행:
CSV·raw·시리얼·영상 경로 / 시간축·접촉 라벨:
관측한 결과 / 해석 / 아직 모르는 것:
다음 행동 / 담당 / 완료 조건:
```

로그는 Git에서 제외된다. 다른 사람이 재분석해야 하는 기록은 보관 위치·파일명·
조건을 함께 남긴다. 날짜 기록은 덮어쓰지 않고 정정을 병기하며, 현재 설명과
백로그는 [노션 문서 규칙](notion_doc_convention.md)에 맞춰 갱신한다.
