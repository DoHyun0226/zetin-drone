## 기준과 범위

기본 지원 코드는 `main`의 `89c5fdb`, 최근 저스로틀 yaw 실험은

각 로컬 브랜치와 해당 원격 참조의 차이는 없었다. 두 브랜치를 통합한 작업은 아니다.

저장소의 현행·보관 펌웨어, 지상국·분석 스크립트, 테스트·CI, 유지 문서와 날짜별
설계·실험 기록을 읽었다. 전체 스케치는 26개(주력 1·보류 1·진단 7·보관 17)다.
실험 브랜치의 변경 파일 24개와 저장된 CSV를 별도로 대조했다. 노션은 ZETIN의
드론 최상위와 하위 12개 페이지를 대상으로 했다.

날짜가 붙은 원문은 보존하고 현재 정정을 병기했다. 구현 파일의 수정은 낡은
주석·문서 문자열에 한정했다. C++ 비주석 토큰과 Python의 문서 문자열을 제외한
AST가 수정 전과 같은지 확인했다.

## 노션 반영 결과

[드론 페이지](https://app.notion.com/p/3142d27b08d3804eb85ced1ca13d8998)와
하위 12개, **총 13개 페이지를 실제 수정한 뒤 다시 조회해 확인**했다.
본문 비교에서는 Notion이 정규화하는 빈 줄·굵은 글씨 경계·물결표 이스케이프만
제외했다. 제목과 최상위 DB의 `요약`·`결과` 속성도 의도한 값과 일치했다.

- 최상위는 소개·현재 상태 네 항목·결과 토글·안전 수칙·마일스톤 골격을 유지했다.
  상태에서 최근 실험의 적용 범위와 다음 작업으로 바로 이동할 수 있게 했다.
- CODE의 펌웨어·지상국·실험 토글과 기존 하위 페이지 12개를 모두 보존했다.
  비어 있던 PCB·CAD에는 자료 위치와 실물 개정 확인이 필요함을 표시했다.
- [지상국·작업 흐름·검증](https://app.notion.com/p/3ae2d27b08d3815f89b9fc0f6fadfcbe)에
  단계별 할 일·다음 단계의 근거·현재 백로그·인수인계 항목을 모았다.
- 설명형 페이지는 기본 코드의 동작·목적·검증 범위로 갱신했다. 날짜가 붙은
  비행 기록 2개는 기존 본문 전체를 한 번씩 보존하고 정정만 앞에 병기했다.
  BOM의 과거 비용·제작시간 산정도 별도 토글 안에 보존했다.

확인은 Notion API의 저장 후 본문·속성·구조 재조회로 수행했다. 브라우저 화면의
육안 검사는 수행하지 않았다. 로컬 문서 변경은 아직 커밋·푸시하지 않았으므로
Notion의 GitHub 링크가 가리키는 원격 문서는 통합 전 내용일 수 있다.
